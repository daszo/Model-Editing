Fixes applied today

uncommitted — see git diff
DOME.py silent wrong results

main() never passed epoch_path, so a missing GR checkpoint only printed a warning and DOME ran its whole edit pipeline against a raw pretrained t5-large that has never seen a docID — plausible-looking, meaningless numbers.

Added --gr_checkpoint (default data/output/t5-large-rq-ckpts/34.pt), passed it through, and made a missing checkpoint raise. Repointed --model_name to ../huggingface/t5-large and the four data files to Edit/data/.

GR/get_docid.py stage 2 crash duplicate docIDs

It emitted only corpus_docids_rq_1, but get_knowns.py reads _1 and _2. It now does both in one run: the RQ quantizer is fit on corpus1, then corpus2 is encoded with those same codebooks. Refitting on corpus2 would give the new documents a codebook inconsistent with the initial collection, which is not what the paper does.

Corpus1’s random collision-digits are carried into the corpus2 pass as reserved, so a new document cannot be handed a docID an initial document already owns. Separately, an RQ code holding more than 128 documents exhausts the digit range — upstream silently assigns 0 and duplicates a docID. That now warns loudly, and the uniqueness check runs across the concatenated corpus.

Smoke-tested on 300 + 20 synthetic documents: 320 docIDs, 0% duplication, and the corpusids[global_docid] positional invariant holds.

GR/get_knowns.py crash at the finish

Edit/data/ is not in the repo and nothing created it, so every write failed after all the work was done. write_json now creates it. Also replaced two list rebuilds sitting inside 100k-iteration loops with a set lookup.

Smoke-tested end to end: emits all seven files DOME reads.

GR/get_vectors.py efficiency

Pads to the longest document in the batch instead of always to 500 tokens — identical embeddings, far less wasted compute. Also dropped a .squeeze() that breaks when the final batch holds exactly one document.

DOME.py, GR/get_knowns.py and GR/get_vectors.py are CRLF upstream and were kept CRLF; GR/get_docid.py is LF.

Watch for

training.py cannot resume

A crash at epoch 40 restarts from epoch 0 with the checkpoint sitting unused — the difference between losing an hour and losing four days. Adding resume (load newest .pt, restore epoch and scheduler position) is the open recommendation before any long run.

GPU memory, in the first minutes

24 GB total, and AdamW in fp32 on t5-large’s 770M parameters is ~12.4 GB before activations. A plain Accelerator() defaults to fp32, which is why the launch above forces bf16. If batch 128 still OOMs, drop to --batch_size 64.

Step rate, before committing the week

1.39M samples per epoch at batch 128 is ~10.9k steps per epoch, ~381k steps across 35 epochs. At roughly 1 s/step that is ~4.5 days — but unmeasured on this 3090. Watch the first hundred steps and extrapolate.
